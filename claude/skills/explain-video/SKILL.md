# explain-video

成果物は作業ディレクトリ（既定は `~/explain-videos/<題名>/`）の 3 ファイル。

- `slides.md`: Slidev のスライド
- `narration.json`: 読み上げ台本
- `video.mp4`: `build.ts` が作る

## 手順

1. 素材を読む。PR なら `gh pr view <n>` と `gh pr diff <n>`、設計なら渡された文書。「何が・なぜ・どう変わるか」を押さえる。
2. `slides.md` を書く。1 枚 1 論点、5〜10 枚。ブラウザで再生して録画するので、Slidev の動きはそのまま動画に入る。
   - スライドの切り替えは headmatter の `transition: slide-left`。スライドごとに frontmatter で変えられる（`fade` など）
   - `<v-click>` / `v-click` / `v-clicks` で箇条や図を順に出す
   - 出方を凝るなら `v-motion`（`:initial` と `:enter` / `:click-1`）
   - コードは ` ```ts {1|3-4|all} ` で行を順にハイライトする。変更前後は `` ````md magic-move `` で見せる
   - 図は ` ```mermaid `
   - クリック 1 回が動画の 1 ステップになる。スライド i のステップ数は「クリック数 + 1」
3. `narration.json` を書く。形は `スライド[] → ステップ[] → 台詞[]`。各ステップに台詞を 1 つ以上置く。

   ```json
   [
     [
       [{ "text": "今回は空の文字列の扱いを変えたのだ", "yomi": "こんかいは、からのもじれつのあつかいをかえたのだ" }],
       [{ "text": "以前は null を返していたのだ", "yomi": "いぜんは、ヌルをかえしていたのだ" }]
     ]
   ]
   ```

   - `text` はテロップ。1 台詞 40 字以内、ずんだもん口調（〜のだ、〜なのだ）
   - `yomi` は読み上げ用。誤読しうる語はひらがな・カタカナで書く。誤読の心配がなければ省略してよい（`text` を読む）
   - 誤読しやすいもの: 同形異音語（空 から/そら、方 かた/ほう、上手 じょうず/うわて）、英字・識別子（`null` ヌル、`Fragment` フラグメント、`PR` ピーアール）、記号、数字と助数詞（`1 行目` を「イチ、クダリメ」と読むので `いちぎょうめ` と書く）、略語
4. 読みを確認する。`bun ~/.claude/skills/explain-video/build.ts <dir> --kana` で各台詞の読みがカタカナで出る。おかしい読みは `yomi` を直して再実行する。
5. 動画を作る。`bun ~/.claude/skills/explain-video/build.ts <dir>`。VOICEVOX が動いていなければ docker で起動する。台本とスライドのステップ数がずれていれば、録画の前に各スライドの実際のステップ数を出して止まる。その数に台本を合わせて再実行する。
6. 確認する。`ffmpeg -i video.mp4 -vf "fps=1,scale=480:-1,tile=6x8" -frames:v 1 sheet.png` で 1 秒ごとのコマを 1 枚に並べて見る。テロップとスライドの対応、文字のはみ出しを見る。気になるコマは `ffmpeg -ss <秒> -i video.mp4 -frames:v 1 x.png` で原寸で見る。

初回だけ `cd ~/.claude/skills/explain-video && bun install` が要る。

## 補足

- 声のスタイルは環境変数 `SPEAKER` で変える（3 ノーマル、1 あまあま、7 ツンツン、22 ささやき）
- 画面は 1920x1080。上 880px にスライド、下にテロップ、右下に「VOICEVOX:ずんだもん」のクレジット（利用規約で必須）
- 各ステップの表示時間は、そのステップの台詞の長さの合計。動きが台詞より長いと途中で次へ進む
- 中間ファイル（台詞ごとの wav と録画した webm）は `<dir>/.build/` に残る。次回の実行で消える
